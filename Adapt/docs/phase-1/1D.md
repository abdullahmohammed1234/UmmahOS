# 3. Implementation Architecture

```text
Challenge
   ↓
Learner Response
   ↓
Evidence Analyzer
   ↓
State Updater
   ↓
Adaptation Engine
   ↓
Next Challenge
```

Physical layout (existing `src/` + Python package conventions):

```text
src/adapt/
├── models/          learner state, challenge, response, evidence, decision
├── analysis/        evidence analyzer
├── state/           state updater
├── adaptation/      engine, selector, challenge bank
├── trace/           decision trace
├── baseline/        baseline tutor + comparison harness
└── pipeline.py      seven-step interaction loop
```

`AdaptPipeline.run` executes the frozen seven-step workflow:

1. Load learner state
2. Present challenge
3. Receive learner response
4. Extract structured evidence
5. Update learner state
6. Select adaptation decision
7. Select next challenge and emit a decision trace

# 4. Chosen State Representation

`LearnerState` is a frozen dataclass, JSON-serializable.

Phase 1C fields:

- `learner_id`, `concept_id`
- `mastery_estimate` — float in `[0, 1]`; an estimate, not ground truth
- `confidence` — float in `[0, 1]`; **diagnostic** confidence (Phase 1C)
- `reasoning_quality` — `STRONG | MODERATE | WEAK | UNKNOWN`
- `error_pattern` — `NONE | CONCEPTUAL | PROCEDURAL | ARITHMETIC | CARELESS | UNKNOWN`
- `misconceptions` — zero or more `{misconception_id, occurrences, status}`
- `recent_performance` — Phase 1C `{correct, incorrect}` counts plus an outcome sequence
- `evidence_strength`, `evidence_reliability`, `learning_trajectory`, `uncertainty`

Phase 1D confidence split (not conflated):

- `learner_confidence` — last expressed learner confidence
- `diagnostic_confidence` — categorical form of the system's diagnosis confidence
- `confidence` — retained Phase 1C diagnostic float

Missing evidence remains `UNKNOWN` / `INSUFFICIENT_EVIDENCE`. Misconceptions are not forced.

# 5. Evidence Representation

`Evidence` is produced from `LearnerResponse + Challenge + history`.

Required Phase 1C/1D fields:

- `answer_status`: `CORRECT | INCORRECT | PARTIAL | AMBIGUOUS | UNKNOWN`
- `reasoning_quality`
- `error_type`
- `misconception_signal` (`null` when unsupported)
- `confidence_signal` (learner-expressed; `UNKNOWN` if absent)
- `evidence_strength`: `STRONG | MODERATE | WEAK | INSUFFICIENT | CONTRADICTORY`
- `diagnostic_confidence`

Implementation extras used by the updater: `evidence_reliability`, `polarity`.

Analyzer rules encoded:

1. Correct + "I guessed." + low confidence → not `STRONG` mastery evidence
2. Correct + strong conceptual reasoning + high confidence → `STRONG` positive evidence
3. Correct + weak reasoning + low confidence → weaker than (2)
4. Incorrect + correct method + arithmetic mistake → `ARITHMETIC`, not automatic `CONCEPTUAL`
5. "Probably B. I'm not sure." → `AMBIGUOUS` and high uncertainty
6. Missing reasoning/confidence → `UNKNOWN`, never fabricated

Correctness is not treated as high reliability.

---

# 6. State-Update Mechanism

Bounded incremental update. New evidence **modifies** state; it does not replace it.

```text
delta = 0.10 * direction * strength_weight * reliability_weight
        [* reasoning_weight if the answer is correct]
        [* 1.25 if the same polarity has already appeared twice]
        [* 0.3 if the new observation contradicts strong history]

delta is clamped to [-0.12, +0.12]
new_mastery = clamp(old_mastery + delta, 0, 1)
```

Direction is `+1` for a correct answer (scaled by reasoning quality), smaller negative values for arithmetic/careless/procedural errors, and `-1` for conceptual errors. Ambiguous / unknown answers do not move mastery.

Other update behaviors:

- Weak evidence produces less movement than strong repeated evidence
- A single response cannot drive mastery to 0 or 1
- Contradictory evidence raises uncertainty (`CONTRADICTORY_EVIDENCE`) and shrinks the mastery step
- Trajectory is computed from the recent outcome window (`IMPROVING / STABLE / REGRESSING / OSCILLATING / UNKNOWN`)
- Diagnostic `confidence` is blended; weak evidence cannot dominate history

---

# 7. Adaptation Rules

Evaluated in this order so that reasons are produced by the firing rule, not invented afterward:

1. Repeated misconception (`occurrences >= 3`) → `REMEDIATE` (or `CHANGE_REPRESENTATION` if `>= 4`)
2. Contradictory evidence → `PROBE_UNCERTAINTY`
3. Insufficient evidence → `GATHER_MORE_EVIDENCE`
4. Weak evidence / high uncertainty → `PROBE_UNCERTAINTY`
5. Reliable regression (trajectory `REGRESSING` and ≥2 consecutive negatives) → `DECREASE_DIFFICULTY`
6. Strong evidence + strong reasoning + high reliability + low uncertainty + consistent recent performance + no active misconception → `INCREASE_DIFFICULTY`
7. Sudden improvement that is not yet a stable mastery signal → `MAINTAIN_DIFFICULTY` (no jump to maximum difficulty)
8. Otherwise → `MAINTAIN_DIFFICULTY`

Every decision contains `decision`, `reason[]`, `confidence`, and `evidence_used[]`. A decision without reasons or an evidence trail is rejected.

# 8. Challenge-Selection Strategy

Concept: `basic_algebra`. Bank of 9 deterministic items:

| ID | Role | Difficulty |
| --- | --- | --- |
| `ALG-E-001`, `ALG-E-002` | practice | EASY |
| `ALG-M-001`, `ALG-M-002` | practice | MEDIUM |
| `ALG-H-001`, `ALG-H-002` | practice | HARD |
| `ALG-D-001`, `ALG-D-002` | diagnostic | EASY/MEDIUM |
| `ALG-R-001` | remediation targeting `DIST_PROP` | EASY |

Selection maps decisions onto the bank:

- `INCREASE_DIFFICULTY` → one step harder practice
- `DECREASE_DIFFICULTY` → one step easier practice
- `MAINTAIN_DIFFICULTY` → same difficulty, different item
- `REMEDIATE` → item whose `target_misconception` matches the repeated misconception
- `PROBE_UNCERTAINTY` / `GATHER_MORE_EVIDENCE` → diagnostic item
- `CHANGE_REPRESENTATION` → different `representation` (symbolic / grouped / worded)

No open-ended content generation.

# 10. Baseline Implementation

`BaselineTutor` (BASELINE-001) receives a challenge and a learner response and returns a diagnosis plus next challenge.

It uses answer correctness only. It does **not** maintain learner state, evidence quality, uncertainty, or misconception records.

A lucky correct guess and a well-reasoned correct answer therefore produce the same baseline next-difficulty move. `compare_sequence` records ADAPT decisions against that correctness-only baseline.

# 14. Known Limitations

- Evidence analysis is keyword/heuristic, not an LLM. It is sufficient to test the workflow, not a general NLP diagnoser.
- Mastery update is a bounded increment, not a calibrated Bayesian learner model.
- The challenge bank covers one concept (`basic_algebra`) and one primary misconception (`DIST_PROP`).
- Challenge selection does not generate novel items; it only selects from the bank.
- Diagnostic confidence is a workflow score, not an empirically calibrated probability.
- No persistence, API, UI, or multi-concept learner model.
- Baseline comparison is a harness, not a completed learning-gain study.
- Thresholds (`0.10` step, `0.12` cap, three-misconception remediation trigger) are implementation choices left unfrozen by Phase 1C.
