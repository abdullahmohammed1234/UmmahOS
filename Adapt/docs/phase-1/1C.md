# Phase 1C — Validated Contract Freeze & Executable Specification

**Project:** ADAPT
**Phase:** 1C
**Status:** Completed
**Purpose:** Freeze the contracts that survived Phase 1B and convert them into a minimal, reproducible, testable ADAPT specification.

---

# 1. Purpose

Phase 1C converts the findings from Phase 1B into the first **validated ADAPT specification**.

Phase 1B attempted to destroy the original contracts.

Phase 1C answers:

> What contracts survived the destruction tests, what must be changed, and what is the smallest executable workflow that can demonstrate genuine adaptation?

The objective is deliberately limited.

ADAPT will not yet optimize architecture, UI, model selection, or production infrastructure.

The goal is to establish a deterministic workflow in which:

```text
Learner Response
        ↓
Evidence
        ↓
Learner State
        ↓
Adaptation Decision
        ↓
Next Challenge
```

can be observed, tested, and evaluated.

---

# 2. Phase 1B → Phase 1C Findings

Phase 1B demonstrated several critical weaknesses.

The original specification incorrectly risked treating:

```text
Correctness = Mastery
```

and:

```text
Accuracy = Learner State
```

It also lacked sufficiently explicit handling for:

* uncertainty
* contradictory evidence
* reasoning quality
* repeated misconceptions
* noisy evidence
* adaptation thresholds
* historical state

These findings are now incorporated into the frozen contracts below.

---

# 3. Frozen ADAPT Workflow

The Phase 1C workflow is:

```text
LEARNER
   ↓
LEARNER STATE
   ↓
CHALLENGE
   ↓
LEARNER RESPONSE
   ↓
EVIDENCE ANALYSIS
   ↓
STATE UPDATE
   ↓
ADAPTATION DECISION
   ↓
NEXT CHALLENGE
```

The central causal chain is:

```text
Response
   ↓
Evidence
   ↓
State Update
   ↓
Decision
   ↓
Next Challenge
```

Every implementation must preserve this relationship.

# 4. Frozen Contract Set

The six contracts from Phase 1B are now frozen with their revisions.

---

## C-001 — Learner State Contract

### Purpose

Represent ADAPT's current belief about the learner using multiple evidence dimensions rather than a single mastery score.

### Required fields

The minimum conceptual learner state is:

```text
learner_id
concept_id
mastery_estimate
confidence
reasoning_quality
error_pattern
misconceptions
recent_performance
evidence_strength
evidence_reliability
learning_trajectory
uncertainty
```

### Rules

1. Correctness must not automatically imply mastery.
2. Missing evidence must remain unknown.
3. Historical evidence must not be silently discarded.
4. Contradictory evidence must be represented.
5. State confidence must be distinguishable from learner confidence.

### Frozen invariant

```text
Correct Answer ≠ Mastery
```

---

# 5. C-002 — Evidence Analysis Contract

### Purpose

Convert a learner response into structured evidence.

### Minimum output

```text
answer_status
reasoning_quality
error_type
misconception_signal
confidence_signal
evidence_strength
diagnostic_confidence
```

### Required answer states

```text
CORRECT
INCORRECT
PARTIAL
AMBIGUOUS
UNKNOWN
```

### Required evidence-strength states

```text
STRONG
MODERATE
WEAK
INSUFFICIENT
CONTRADICTORY
```

### Rules

A correct answer with weak reasoning must not produce the same evidence profile as a correct answer with strong reasoning.

An incorrect answer with correct conceptual reasoning must not automatically become evidence of conceptual misunderstanding.

---

# 6. C-003 — Challenge Selection Contract

### Purpose

Select the next instructional action based on the learner state.

### Allowed decisions

```text
INCREASE_DIFFICULTY
MAINTAIN_DIFFICULTY
DECREASE_DIFFICULTY
REMEDIATE
PROBE_UNCERTAINTY
CHANGE_REPRESENTATION
GATHER_MORE_EVIDENCE
```

### Required inputs

Challenge selection must receive:

```text
learner_state
current_concept
recent_evidence
available_challenge_metadata
```

### Critical invariant

Challenge selection must not rely on accuracy alone.

The decision must be explainable through learner-state evidence.

---

# 7. C-004 — State Update Contract

### Purpose

Integrate new evidence with the existing learner state.

### Update model

Conceptually:

```text
Previous State
      +
New Evidence
      +
Evidence Reliability
      +
Historical Pattern
      ↓
Updated State
```

### Rules

1. New evidence modifies the existing state.
2. Weak evidence produces limited state movement.
3. Strong repeated evidence produces stronger state movement.
4. Contradictory evidence reduces certainty rather than forcing an arbitrary classification.
5. A single response cannot automatically erase historical evidence.

### Frozen invariant

```text
New Evidence ≠ Complete State Replacement
```

---

# 8. C-005 — Adaptation Boundary Contract

### Purpose

Determine when evidence is sufficient to change the learner's instructional trajectory.

### Decision principles

### Increase difficulty

Requires sufficient positive evidence.

### Maintain difficulty

Used when evidence is insufficient for a meaningful trajectory change.

### Decrease difficulty

Requires meaningful evidence of difficulty or regression.

### Remediate

Triggered by a sufficiently reliable misconception pattern.

### Probe uncertainty

Used when competing learner-state hypotheses remain plausible.

### Gather more evidence

Used when the current evidence is insufficient to justify a major decision.

### Frozen invariant

```text
Weak Evidence → Conservative Adaptation
Strong Repeated Evidence → Stronger Adaptation
```

---

# 9. C-006 — Uncertainty Contract

### Purpose

Prevent ADAPT from manufacturing certainty.

### Required uncertainty states

```text
LOW_UNCERTAINTY
MODERATE_UNCERTAINTY
HIGH_UNCERTAINTY
INSUFFICIENT_EVIDENCE
CONTRADICTORY_EVIDENCE
```

### Rule

When evidence cannot reliably distinguish between competing learner-state hypotheses, ADAPT must preserve uncertainty.

The system may choose:

```text
PROBE_UNCERTAINTY
```

or:

```text
GATHER_MORE_EVIDENCE
```

rather than forcing:

```text
MASTERED
```

or:

```text
NOT_MASTERED
```

# 10. Unified Learner Evidence Object

The contracts are unified around the following conceptual object:

```json
{
  "answer_status": "CORRECT",
  "reasoning_quality": "STRONG",
  "error_type": null,
  "misconception_signal": null,
  "confidence_signal": "HIGH",
  "evidence_strength": "STRONG",
  "diagnostic_confidence": "HIGH"
}
```

A different response could produce:

```json
{
  "answer_status": "CORRECT",
  "reasoning_quality": "WEAK",
  "error_type": null,
  "misconception_signal": "POSSIBLE",
  "confidence_signal": "LOW",
  "evidence_strength": "WEAK",
  "diagnostic_confidence": "LOW"
}
```

Both responses are correct.

They must **not** necessarily produce the same learner-state update.

# 12. Adaptation Decision Object

Every adaptation decision must be explainable.

Minimum conceptual structure:

```json
{
  "decision": "INCREASE_DIFFICULTY",
  "reason": [
    "strong_recent_evidence",
    "high_reasoning_quality",
    "low_misconception_signal"
  ],
  "confidence": "HIGH",
  "evidence_used": [
    "response_001",
    "response_002",
    "response_003"
  ]
}
```

A decision without an evidence basis is considered invalid.

# 13. Counterfactual Requirement

The counterfactual test from Phase 1B becomes a permanent ADAPT invariant.

Consider:

```text
Learner A
Correct
Strong reasoning
High confidence
No misconception
```

and:

```text
Learner B
Correct
Weak reasoning
Low confidence
Repeated misconception
```

The system must be capable of producing:

```text
Learner A
→ INCREASE_DIFFICULTY
```

while:

```text
Learner B
→ REMEDIATE
or
→ GATHER_MORE_EVIDENCE
```

The exact action may vary.

The critical requirement is:

```text
Different Evidence
        ↓
Different State
        ↓
Potentially Different Decision
```

This is the primary operational definition of ADAPT's adaptivity.

---

# 14. Minimal Executable Workflow

Phase 1C reduces the system to seven executable steps:

```text
1. Load learner state
2. Present challenge
3. Receive learner response
4. Extract structured evidence
5. Update learner state
6. Select adaptation decision
7. Generate next challenge
```

This workflow is sufficient for the first prototype.

No additional agent, database, retrieval layer, or complex orchestration is required to demonstrate the core hypothesis.

---

# 15. Decision Trace Requirement

Every interaction must produce a trace.

Example:

```text
Interaction:
I-004

Learner Response:
Correct

Evidence:
Correct answer
Strong reasoning
High confidence

State Before:
Mastery = 0.62
Uncertainty = MODERATE

State After:
Mastery = 0.71
Uncertainty = LOW

Decision:
INCREASE_DIFFICULTY

Reason:
Repeated strong evidence of conceptual understanding
```

This trace is required because ADAPT's decisions must be auditable.

# 16. Minimum Test Suite

The following tests become mandatory for the first implementation.

### Test A — Correct + Strong Reasoning

Expected:

```text
Positive evidence
```

### Test B — Correct + Weak Reasoning

Expected:

```text
Weaker evidence
```

### Test C — Incorrect + Correct Conceptual Reasoning

Expected:

```text
Execution/procedural error
```

rather than automatic conceptual failure.

### Test D — Repeated Misconception

Expected:

```text
REMEDIATE
```

or:

```text
GATHER_MORE_EVIDENCE
```

### Test E — Insufficient Evidence

Expected:

```text
UNCERTAIN
```

rather than confident mastery.

### Test F — Counterfactual Learners

Expected:

```text
Different evidence
→ Different state
→ Different potential decision
```

# 17. Baseline Definition

The baseline is frozen as:

```text
BASELINE-001

A single structured tutoring prompt receives:
- learner question/context
- learner response
- available conversation history

and directly generates:
- diagnosis
- explanation
- next challenge
```

The baseline does not maintain the explicit ADAPT learner-state → evidence → decision pipeline.

---

# 18. ADAPT vs Baseline Evaluation

The first evaluation will compare the two systems on:

| Metric                         | Purpose                                           |
| ------------------------------ | ------------------------------------------------- |
| Counterfactual Differentiation | Does different learner evidence change decisions? |
| Misconception Detection        | Can repeated misconceptions be identified?        |
| Uncertainty Handling           | Does weak evidence remain uncertain?              |
| Difficulty Appropriateness     | Are difficulty changes justified?                 |
| State Consistency              | Does learner state remain coherent?               |
| Decision Traceability          | Can decisions be explained through evidence?      |

The goal is not to claim superiority before testing.

The goal is to establish a reproducible experiment capable of falsifying the ADAPT hypothesis.

# 22. Phase 1C Final Result

**STATUS: PASS — CONTRACTS FROZEN**

ADAPT now has a sufficiently precise specification to begin implementation and empirical evaluation.

The project is no longer based on the assumption:

> "Multiple prompts will make the tutor adaptive."

Instead, the testable hypothesis is:

> **An explicit evidence-driven learner state can cause ADAPT to select more appropriate subsequent learning actions than a single structured tutoring prompt.**

The implementation must now test this hypothesis rather than assume it.

The next phase begins from the frozen contracts defined here.
