## 1. Objective

Phase 1–3 established that ADAPT's adaptive engine works.

Phase 4 asks a different question:

> Can a real learner experience ADAPT's adaptation clearly, naturally, and convincingly?

The product must make this loop tangible:

```text
Learner
   ↓
Challenge
   ↓
Response
   ↓
ADAPT analyzes
   ↓
Learner state changes
   ↓
Strategy changes
   ↓
Next challenge changes
   ↓
Learner continues
```

The UI exposes the intelligence already validated in Phase 3. It does not replace the adaptive engine with frontend logic.

---

## 2. Product Hypothesis

**H1:** A learner-facing product that only submits `answer`, `confidence`, and `reasoning` to `AdaptiveTutor`, then renders the returned evidence → state → strategy → challenge chain, can make adaptation visible without duplicating Phase 1–3 decision logic.

**H0:** The product layer invents or alters adaptive decisions, or a learner/judge cannot observe the causal chain without reading the code.

This phase tests the **product boundary**, not a new algorithm.

## 4. Architecture

No frontend existed. Phase 4 added a product layer around the frozen `AdaptiveTutor`.

```text
Learner UI (src/app/static)
        ↓  answer, confidence 1–5, reasoning
HTTP API (src/app/server.py)     stdlib only
        ↓
ProductService (src/adapt/product/service.py)
        ↓  LearnerResponse
AdaptiveTutor (Phase 3, unchanged)
        ↓
EvidenceAnalyzer → StateUpdater → AdaptiveStrategyEngine → AdaptiveChallengeSelector
        ↓
StepTrace
        ↓
Product presentation (feedback, learner strategy copy, research chain)
```

Rules enforced:

- Frontend never contains `if (correct) increaseDifficulty()` or equivalent.
- Learner views do not include `expected_answer` or raw mastery as a scoreboard.
- Adaptation headlines are templates keyed off **actual** `StrategyName` and `reason_codes`.
- `demo/scenario.json` stores **input kinds only**. Displayed strategies and next challenges are computed live.

Supported topics only: Algebra (`basic_algebra`, start `ALG-D-001`), Fractions (`fractions`, start `FR-D-001`).

## 5. Learner Experience

Landing sentence: *A tutor that adapts to how you learn.*

Session screen: challenge prompt, required answer, 1–5 confidence, optional reasoning with the explanation that reasoning helps ADAPT understand what the learner knows.

After submit: processing state, duplicate submit blocked, feedback from `Evidence.answer_status` / `reasoning_quality`, then an adaptation card when the engine decides the next move.

Understanding is shown as a bar derived from mastery estimate, labeled **Understanding**, not “mastery score.”

Progress is `Challenge k of n` and is not gated on correctness.

---

## 6. Research / Demo View

Research view shows one complete link per step:

```text
Response
   ↓
Evidence
   ↓
Learner state (numeric mastery / confidence, arrows)
   ↓
Strategy + engine reason
   ↓
Next challenge ID
```

Plus a strategy timeline (`Step 1 GATHER_EVIDENCE`, `Step 3 INCREASE`, …).

This is the project's core technical story. It is not a percentage dashboard.

## 7. Adaptation Visualization

Learner-facing strategy copy (never the raw enum as the primary message):

| Engine strategy | Learner message |
| --- | --- |
| INCREASE | You're showing strong understanding. Let's raise the challenge. |
| MAINTAIN | You're progressing well. Let's reinforce this level with another variation. |
| PROBE | Let's try a quick check to understand this concept more clearly. |
| REMEDIATE | Let's approach this concept from another angle. |
| GATHER_EVIDENCE | Let's try one more challenge before deciding what comes next. |
| DECREASE | Let's step back and build this up from a simpler version. |
| ASSESS | Let's start by seeing how you approach this concept. |
| RECOVER | Your responses improved. Let's move forward from here. |

Supporting sentences are selected from actual `reason_codes`. If no code matches, the strategy message is reused. Engine `reason` is always available in the research view.

**How ADAPT adapted** is a chronological beat list generated from traces (start → evidence beats → strategy beats). It is not a canned story.

## 9. Session Model

`ProductSession` metadata (topic, max steps, demo script cursor, analytics timestamps) wraps `TutorSession`. Snapshot/restore serializes both. Isolation is inherited from `AdaptiveTutor` (separate session IDs, no shared learner state).

Default session length: 10 challenges. Demo: 9 scripted steps from `demo/scenario.json`.

Analytics stored locally per session: step, challenge, response id, strategy, mastery, timestamp. No accounts. No third-party tracking.

## 14. Failures

No application-level benchmark session failed completion or preservation.

Documented product/engine mismatches versus the *illustrative* Phase 4 cartoon (not scored failures):

1. The first strong-correct step is `GATHER_EVIDENCE`, not `INCREASE`. Sparse-evidence gather-before-commit is frozen Phase 2/3 behavior. The UI shows that honestly.
2. After remediation recovery, the exposed strategy is `GATHER_EVIDENCE` (internal `RECOVER` is not the learner-facing enum). The story beat still records “ADAPT recognized recovery and moved you forward” because the session left `REMEDIATE`.
3. Guided demo is 9 steps, not 8, because three misconception responses are required before the frozen engine enters `REMEDIATE`.
4. Step 9 engine reason is conflicting-evidence gather, not a slogan-like “you have recovered.” The research view shows the actual reason.
5. Session summary “strongest area” / “area to keep practicing” collapses to one concept when the session stays on a single topic. That is correct, not a dashboard fake.

## 15. Limitations

- Evidence analysis remains keyword/heuristic. The product cannot explain more than the engine observed.
- No LLM was introduced for UI copy generation.
- Formative usability is untested.
- M4-004/M4-005 n=5; Wilson intervals are wide.
- Vanilla HTML/JS SPA, stdlib HTTP server, local only. Not a production deployment.
- Confidence 1–5 is mapped onto `{LOW, MODERATE, HIGH}`; the engine has no 5-level confidence type. That mapping is product-layer, not a change to `LearnerConfidence`.
