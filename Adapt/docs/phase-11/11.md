---

## 1. Purpose

Transform the Phase 10 Next.js learner application from a functional prototype into a polished, competition-quality learning product.

The product promise remains **Learn differently.**

The technical story remains:

```text
Different evidence
        ↓
Different learner state
        ↓
Different strategy
        ↓
Different challenge
```

Phase 11 makes that story easier to see. It does not change AdaptiveTutor.

---

## 2. Design goals

- Visually distinctive, calm, educational, trustworthy
- Simple learner path; technical detail in Research Mode
- Fast challenge interaction (answer, confidence, optional approach)
- Concise, trace-backed explanations
- Memorable adaptation moment
- Responsive and accessible
- Competition-demo friendly within about 30 seconds of landing

Avoided: extra dashboards, walls of copy, decorative 3D, gamification, engine changes.

---

## 3. Architecture

```text
Browser
   ↓
Next.js (frontend/)
   ↓
typed API client
   ↓
Python API (src/app/server.py)
   ↓
ProductService
   ↓
AdaptiveTutor
```

React never chooses mastery, strategy, difficulty, misconception, learner state, or next challenge.

---

## 4. Frontend changes

- Centralized design tokens in `frontend/app/globals.css`
- Landing hero: **Learn differently.**, one supporting sentence, visual Answer → ADAPT notices → ADAPT adapts
- Subject cards with domain motifs; Quantum is visually distinct; Space has a constellation metaphor
- Concept discovery: search, recommended, recently explored, grouped by topic
- Challenge screen: question-dominant, emoji confidence, approach chips, optional explanation
- Feedback story: Correct / Not quite → What ADAPT noticed → ADAPT ADAPTED → Why this question? → Here’s what’s next
- Intentional repetition copy: “Let's try this idea from another angle.”
- Research Mode and live counterfactual preserved
- Human-readable loading/error/empty states

## 7. Animation strategy

Framer Motion for page/challenge/feedback transitions, adaptation reveal, subject hover, and counterfactual entrance. CSS for pulse/focus. All honor `prefers-reduced-motion`. Animations do not block Continue.

---

## 8. Three.js usage

Three.js remains **Quantum-only**, lazy-loaded, labeled as a Bloch-sphere-inspired metaphor (not a simulator). Space uses CSS/SVG constellation. Landing uses CSS/SVG. Challenge screens stay 2D.

## 9. Accessibility

Skip link, `lang="en"`, focus rings, labeled controls, `role="radiogroup"` for confidence, `aria-live` feedback, alert/status roles, button contrast (white on teal; ink on cream), research-mode checkbox label, reduced motion.
