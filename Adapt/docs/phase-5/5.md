## 1. Research Question

Primary:

> Does an adaptive tutoring workflow produce greater learner improvement than a fair non-adaptive tutoring workflow?

Secondary:

1. Does ADAPT improve misconception recovery?
2. Does ADAPT better match challenge difficulty to learner evidence?
3. Do learners perceive ADAPT as more adaptive?
4. Does ADAPT produce measurable differences in learning gain?
5. Are any observed differences large enough to be practically interesting?

---

## 2. Hypotheses

Frozen before inspecting participant outcomes.

**H1:** Learners using ADAPT will demonstrate greater pre-test to post-test learning gain than learners using the baseline tutoring workflow.

**H0:** There is no meaningful difference in learning gain between ADAPT and the baseline.

Secondary:

- **H1a:** ADAPT will produce better misconception recovery.
- **H1b:** Learners will perceive ADAPT as more responsive to their demonstrated understanding.
- **H1c:** ADAPT will produce more appropriate challenge transitions.

These hypotheses may be unsupported. Analysis rules were not altered after seeing (the absence of) human results.

Frozen interpretation rule:

| Human n | Rule |
| --- | --- |
| n < 1 | **INCONCLUSIVE** |
| 1 ≤ n < 6 | Exploratory evidence only. Directional support only if every paired delta has the same sign. |
| n ≥ 6 | Wilcoxon signed-rank plus bootstrap 95% CI on mean delta. H1 supported only if median delta > 0 and the CI excludes 0. |

## 5. Conditions

### ADAPT

Participants would use the real Phase 4 product: `ProductService` → `AdaptiveTutor`.

- 4 algebra steps starting at `ALG-D-001`
- 4 fractions steps starting at `FR-D-001`
- Next challenge originates from AdaptiveTutor
- Recorded: challenge id, answer, confidence, reasoning, evidence, learner state, strategy, next challenge, timestamp, trace id

Verified on a scripted application-boundary flow (not a human):

```text
ALG-D-001 strong_correct → GATHER_EVIDENCE → ALG-P-001
ALG-P-001 weak_correct   → PROBE           → ALG-P-002
ALG-P-002 misconception  → MAINTAIN        → ALG-E-003
ALG-E-003 strong_correct → MAINTAIN        → ALG-E-004
```

Each step had a complete Evidence → State → Strategy → Next challenge link.

### BASELINE

`LinearTutor` in `src/adapt/eval/baseline.py`. This is a new Phase 5 evaluation tutor, not the Phase 1D correctness-only helper and not the Phase 1E decision-appropriateness baseline.

Frozen 8-item sequence (same for all learners; order does not depend on mastery or strategy):

`ALG-E-001`, `ALG-M-001`, `ALG-D-001`, `ALG-M-002`, `FR-E-001`, `FR-M-001`, `FR-D-001`, `FR-P-001`

Properties:

- Same concepts (algebra + fractions)
- Comparable difficulty mix and item count (8)
- Feedback after every answer
- Deterministic
- Does not import or call AdaptiveTutor, ProductService, strategy, or state update
- Does not use mastery to choose the next item

Unavoidable difference: ADAPT’s item path depends on evidence; the baseline path is fixed. That is the independent variable.

## 7. Pre-test

Frozen 8-item form `PRETEST` (`PRE-A-001` … `PRE-F-004`).

Each item has id, concept, difficulty, correct answer, accepted aliases, and scoring rule `normalized_exact_or_alias`.

Learner-facing views omit correct answers.

---

## 8. Training Procedure

1. Pre-test (no feedback on keys).
2. Condition A (4+4 items).
3. Post-test for that condition.
4. Survey Q1–Q5 plus two open items.
5. Condition B (4+4 items).
6. Post-test for that condition.
7. Survey again.

ADAPT training is submitted through `ProductService.submit_response`. Baseline training is submitted through `LinearTutor.submit`.

---

## 9. Post-test

Two equated 8-item forms:

- After ADAPT: `POSTTEST_ADAPT`
- After BASELINE: `POSTTEST_BASELINE`

`gain = post_test_score - pre_test_score`

Training questions are not reused as post-test questions.

## 12. Statistical Method

Chosen before outcomes:

- Design: paired within-subject delta `gain_ADAPT − gain_BASELINE`
- Small n: mean, median, sd, participant-level trajectories
- Effect size: Cohen’s *d<sub>z</sub>* when n ≥ 2 and sd > 0
- Inferential: Wilcoxon signed-rank and bootstrap 95% CI only if n ≥ 6
- No t-test by default
- No alternative-test fishing

With n = 0 none of the numeric summaries are defined. Report: **Exploratory evidence only.** Human H1: **INCONCLUSIVE**.

## 15. Misconception Recovery

Predefined scenarios:

- `MR-DIST-PROP` (distribution)
- `MR-ADD-DENOM` (adding denominators)

Recovery requires observed misconception evidence during training **and** a later equivalent item that is correct **with conceptual reasoning**. A lucky correct answer without reasoning is not recovery. Unobserved misconceptions are `NOT_APPLICABLE`.

Human comparison: NOT COLLECTED. Automated tests cover lucky-correct, conceptual recovery, and not-applicable cases.

## 18. Threats to Validity

- Small sample size (here, n = 0)
- Order effects
- Practice effects
- Topic familiarity
- Question difficulty / form inequivalence
- Participant selection (none recruited)
- Short study duration
- Interface differences
- Baseline quality
- Novelty effect
- Measurement error (heuristic scoring and evidence)

These threats are why n = 0 is reported as INCONCLUSIVE rather than as support or rejection of H1.
