# Phase 10 — ADAPT 2.0 Frontend Reconstruction

**Project:** ADAPT  
**Phase:** 10  
**Status:** COMPLETE — PASS  
**Frontend:** Next.js 15 / React 19 / TypeScript / Tailwind CSS / Framer Motion  
**API:** existing Python `ProductService` on port 8765  

The adaptive engine was not redesigned. Historical Phase 1–9 artifacts were not rewritten. Phase 5 remains INCONCLUSIVE (n=0). No educational-efficacy claim was added.

---

## 1. Objective

Transform the Phase 9 learner interface from a functional prototype into a polished learning product:

Choose → Learn → Answer → ADAPT notices → ADAPT adapts → Improve

without replacing:

Response → Evidence → State → Strategy → Next Challenge

---

## 2. Previous UI limitations

The Phase 9 static UI was complete enough to demonstrate the engine, but it still felt like a Python prototype:

- Single HTML file with template strings
- Limited motion and visual hierarchy
- Adaptation was visible, but not memorable
- Subject cards were similar
- Quantum was first-class in content, less so in presentation

Phase 10 keeps that UI available at `http://127.0.0.1:8765` and introduces a Next.js product at `http://127.0.0.1:3000`.

---

## 3. Architecture

```text
Browser
   ↓
Next.js (frontend/)
   ↓
typed API client
   ↓
Python API (src/app/server.py)
   ↓
ProductService
   ↓
AdaptiveTutor
   ↓
Evidence / State / Strategy / Challenge
```

React never chooses a strategy or next challenge. It submits `answer`, `confidence`, `approach`, and optional explanation, then renders the returned trace.

---

## 4. Frontend stack

- Next.js App Router
- React + TypeScript
- Tailwind CSS
- Framer Motion
- React Three Fiber, used only for the Quantum subject visual

No Vue. No extra state library. No LLM.

---

## 5. Design system

Restrained paper-and-ink system:

- Display type: Instrument Serif (`Learn differently.`)
- UI type: Plus Jakarta Sans
- Canvas `#F4F1EA`, ink `#161513`, accent `#0F6B57`
- Domain accents for the seven subjects
- Cards, pills, focus rings, reduced-motion support

Motion is short and purposeful: hover lift, challenge/feedback transition, adaptation reveal.

---

## 6. Product changes

- Landing: ADAPT, Learn differently., supporting sentence, dual CTAs, learner chain, seven domains
- Subject exploration with domain-specific SVG motifs
- Quantum Bloch-sphere metaphor (labeled as a metaphor, not a simulation)
- Learning screen: question-dominant, 3-level confidence, approach chips, optional explanation
- Concise feedback, What ADAPT noticed, Why this question?
- Adaptation moment when the engine returns a decision
- Research Mode remains optional and visually separated
- Counterfactual remains two live AdaptiveTutor runs
- Progress labeled as session/visit memory

---

## 7. API integration

The existing Python routes are sufficient. Next.js rewrites `/api/:path*` to `http://127.0.0.1:8765/api/:path*`.

Confidence mapping remains the engine 1/3/5 scale (`Guessing` / `Unsure` / `Confident`). Approach ids remain `{knew, worked, pattern, guessed, unsure}`.

---

## 8. Adaptation UX

The adaptation moment is the primary product beat:

Your response → ADAPT notices → ADAPT decides → Next challenge

Learner copy uses `LEARNER_STRATEGY` / product explanations. Raw enums are reserved for Research Mode.

If the engine remediates, the UI says “Let's revisit this idea.” It does not hide repeated challenge IDs.

---

## 9. Quantum / 3D work

Three.js is used on the Quantum subject page only. The scene is a spherical state metaphor with a moving marker. Copy states it is not a physics simulation. Challenge screens stay 2D so the question remains readable.

---

## 10. Responsive design

Layouts stack on narrow screens. The challenge form remains one column. Navigation collapses to a menu. Confidence choices become a 3-row stack on mobile.
